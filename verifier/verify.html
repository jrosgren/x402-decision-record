x402 decision record verifier

Supports schema v1.0 (release candidate; freeze planned 24.11.2026, tagged release v1.0.0 by 25.11.2026) and legacy v0.2-draft.

Example data. The sample records on this page are made-up illustrations, not live Payvetted decisions. Payvetted is pre-launch and does not issue production records yet.

Nothing leaves the browser. This page makes no network requests. The record and the public key are checked only on this device.

Paste a record or load an example, then click Verify.

How the check works

The signature is Ed25519 over the RFC 8785 (JCS) canonical JSON of the record with the signature field removed. This page hashes those canonical bytes with SHA-256 and checks the signature with the public key you paste (Web Crypto when the browser supports Ed25519, otherwise an inlined tweetnacl.js fallback). The demo key id is polkulab-demo-2026-11. A third party can run the same check with the Python script or OpenSSL commands in the README, with no access to Polkulab systems.

For v1.0 records the page first validates the record against the v1.0 JSON Schema (embedded in the page; same rules and error codes as verify.py), including the signature object (exactly alg, key_id, sig_base64), canonical base64, timestamps (seconds or exactly milliseconds, with Z) and integers within ±(253−1). It rejects signatures with S ≥ L on every path, including the tweetnacl fallback. It then checks the keyset (version, unique key ids, optional SHA-256 anchor, validity window and revocation), the signature, every inline evidence hash, the timeline, and, if you supply them, the payment binding against x402 v2 payment requirements and the linked record hashes. See SPEC.md §11 for the exact steps.
